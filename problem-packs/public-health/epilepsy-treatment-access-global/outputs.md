# Expected outputs

The pack is an evidence and decision-support protocol. Outputs become canonical only through the task status and review gates in `tasks.json`.

## V0 outputs

- A dated source inventory separating usable, limited, and rejected source families.
- A stage-level measure dictionary with case definitions, numerators, denominators, event dates, grain, missingness, and linkage rules.
- One setting-specific cascade baseline with an input hash, environment note, reproducible command, and explicit uncertainty.
- A structured red-team record covering clinical overreach, privacy, inequity, denominator error, and procurement misuse.
- A field-reality brief naming the responsible user, decision, timing, minimum evidence, and non-use cases.

## Publication boundary

No output may be published as a patient-level diagnosis, medication instruction, seizure forecast, or automatic country ranking. A programme-facing output must state whether it measures population need, diagnosis, stock, dispensing, possession, adherence, seizure control, referral, or outcome. If the source cannot distinguish those stages, the output must preserve the ambiguity or stop.

## Replication artifact requirements

Any quantitative output must include:

- source file names or URLs and access dates;
- input hash and environment details;
- code or exact calculation steps;
- denominator and missingness rules;
- a sensitivity or alternative-definition check;
- the observation that would falsify the proposed bottleneck;
- independent replication status.
